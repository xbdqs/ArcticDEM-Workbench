# 0.9.0 验证记录

本记录对应 0.9.0 源码及 `validation/v090` 中的实际执行结果。测试环境为 Linux、Python 3.12.14、Qt offscreen；不能替代用户 Windows 显示和二进制依赖检查。本轮没有新增 ArcticDEM 野外精度结果。

## 回归与界面

`validation/v090/regression/tests.log`：**69 项测试全部通过**。其中新增 11 项检查覆盖导数方向、空洞/边界、平地分类、地形组完整划分、空间偏差、稀疏块、边缘块尺寸、参数有效默认值、同支持指标差、比较条件异常和诊断资源上限。

完整集成检查包括项目保存/恢复、固定点与目标区、已有案例模板、共同覆盖、报告导出以及 GUI 截图。`verification.json` 记录实际版本和输出校验值。界面截图仅表示本环境的窗口能够布局和绘制，不声称已在 Windows 上显示验证。

## 四期时序检查

相同的四期合成数据分别通过 vertical、translation 和 nuth_kaab 完成计算。最终共同有效像元 **64,256**，共同验证像元 **10,523**。集成测试导出两个固定点、四个日期、三个方法，共 **24 行**点序列；目标区固定为 2,304 个像元。

| 方法 | 预设首末期目标区平均高差（m） | 实际面积加权平均高差（m，表内舍入） |
|---|---:|---:|
| vertical | −12 | −11.999360 |
| translation | −12 | −12.000096 |
| nuth_kaab | −12 | −11.999099 |

三种方法均保持预设变化。0.2 m 是该合成验收脚本的工程检查容差，不是遥感精度声明或真实案例的检出阈值。完整数值保存在 `verification.json` 和 `region_pair_statistics.csv`。

## 扩展受控实验

`validation/v090/extended/benchmark_summary.json` 记录 **48 组场景、192 条方法记录、0 个意外检查结果**。固定种子为 42、1729、20260913，网格大小为 160 和 256；种子只是可复现整数，不表示观测日期。

| 检查类别 | 记录数 | 解释 |
|---|---:|---|
| 在预设容差内 | 54 | 适用模型下的参数与变化保留检查 |
| 预期拒绝 | 48 | 无重叠、支持不足等场景正确停止 |
| Raw 基线未评分 | 48 | 用于保留未配准对照 |
| 垂向基线未评分 | 24 | 不把仅估计垂向的方法当作水平平移恢复方法 |
| 模型失配未评分 | 18 | 保留未建模倾斜等场景的局限 |

因此不能写成“192 项精度检验全部通过”。原始记录、场景输入数组、共同掩膜及图表均保存在该目录。

与 0.8.0 的扩展实验逐行比较，除 `elapsed_seconds` 外，192 条记录所有字段均一致，见 `scientific_baseline_comparison.json`。`coreg.py`、`network.py` 和 `requirements.txt` 也保持原有内容。本版的改变集中于结果诊断和交付流程。

同一固定点跨三个方法和四个日期导出 12 行，共同有效/验证像元数保持 64,256 / 10,523。该项检查确认导出过程不重新拟合且不修改源结果，不能证明真实输入的科学适用性。

## 证据文件与适用边界

发布包原样保存验证记录的字节，避免改写 JSON 路径破坏内部校验。记录中可能包含执行当时的绝对路径，这是来源信息；不保证这些临时运行目录在另一台计算机可访问。随包 HTML 内嵌预览可直接阅读；`RUN_07_REPORT_DIAGNOSTICS_DEMO.bat` 用于在本机生成完整新案例。

为减少重复数据，发布包的演示目录保留验收记录和导出报告，省略该演示的临时原始 DEM、完整比较工作区及重复 ZIP。扩展实验的场景数组仍提供。`RELEASE_MANIFEST.json` 列出实际包含文件及 SHA-256；构建时执行 ZIP CRC 和清单逐文件校验。

尚待补充的证据包括：本版 Windows 本机验收；外部实现验证 0.1.2 的用户恢复结果；真实案例资料的统一时段/边界比较；独立实测参照；空间相关的区域不确定度模型。当前状态应写为“可复现内部诊断与受控软件验证完成”，不能写成“全域地表变化产品已通过外部验证”。
