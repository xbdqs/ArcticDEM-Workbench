# 共同范围与固定区域统计 · v0.6.0

本功能读取已经完成的结果，重新计算共同范围内的描述性统计，不重新配准。只要旧结果目录内保留 `report.json`、`epoch_stack.tif`、`registered_common_valid_mask.tif`、`fit_mask.tif` 和 `validation_mask.tif`，通常可以直接导出。默认一次比较使用同一个比较任务根目录下已完成的方法；普通单次结果也可导出，但会标明没有跨方法比较。

## 怎样操作

1. 在 **3 Results / time series** 打开一个已完成结果。比较任务可以打开其中任一方法子目录，软件会识别同级比较清单。
2. 在 **6 Case project** 导入目标区域 GeoJSON，角色设为 `target`。也可以 **Store current AOI…** 后选中该对象，用 **Set role…** 改为 `target`。它是统计边界，不会重做已有结果的分析区。
3. 点击 **Export report + point series…**。完成后点击 **Open report** 查看表格，**Show common support** 查看实际共同覆盖，**Export folder** 打开文件目录。
4. 检查区域覆盖率和有效面积，再比较数值。保存项目可保留最近报告位置。

下载前的 **Show checked common footprint** 仍表示条带几何足迹交集；新功能表示下载、质量筛选和配准之后实际有效的像元交集。两者服务于不同阶段。

## 固定范围的定义

设已完成并纳入统计的方法为 \(m\)，所选时相为 \(t\)，保存的分析区为 \(A\)，方法 \(m\) 在时相 \(t\) 的有效像元集合为 \(V_{m,t}\)。统计范围为：

\[
S=A\cap\bigcap_m\bigcap_t V_{m,t}.
\]

所有方法、所有两期组合使用同一集合 \(S\)。它比较保守：增加一个覆盖差的时相可能显著缩小共同范围。当前版本不会在某个时相缺测时悄悄改用较少时相，也不会自动改成每对日期不同的范围。零共同覆盖时仍输出掩膜和覆盖记录，变化统计留空。

计算前核对：时相 ID、日期和顺序、来源 DEM/质量掩膜哈希、共享影像信息、垂直基准、栅格 CRS/仿射变换/尺寸以及保存的分析区像元。网格或分析区不一致时拒绝共同范围计算，不为凑齐网格而再次插值。该部分不可用时，普通逐方法报告仍可导出，原因写入报告和 `common_support/status.json`。

失败方法被单独列出。若只剩一个已完成方法，则结果仅有固定时间支持，不能称为多个方法对比。额外的处理参数差异会在记录中提示，因此不能把掩膜一致或共同像元一致自动解释为“只有方法不同”的受控实验。

## 共同验证像元

令 \(H_m\) 和 \(F_m\) 分别表示某方法结果保存的留出区与拟合区像元，则：

\[
H^*=\left(S\cap\bigcap_m H_m\right)\setminus\bigcup_m F_m.
\]

新的验证表在 \(H^*\) 上，使用最终配准栈的两期高差计算中位数、NMAD、相对零变化的 RMSE 和绝对值 95% 分位数。零变化参照依赖留出区在对应时段稳定这一科学前提。少于 64 个像元或不足三个报告空间块时标记 `limited_support`；没有有效验证像元时为 `no_validation_support`。这不是显著性检验，也不输出新的检出限。

使用相同的输出像元中心有助于公平比较，但不能证明统计独立：配准后的采样位置、插值邻域、共享源 DEM 和空间依赖仍可能关联拟合与验证。报告沿用原始 `validation_kind`，不把内部留出包装成外部独立验证。若根据该表选了方法，还需另外的数据评价最终精度。

报告前部保留原有逐方法独立边诊断，后部新增共同像元上的最终栈诊断。两者处于不同处理阶段，不应将前者的 NMAD 与后者当作同一个量进行混合排名。

## 区域高差与体积

目标多边形按照像元中心落入规则栅格化，保留孔洞及多部件。设目标区域为 \(R_k\)，共同可观测部分为 \(R_k\cap S\)，像元地面面积为 \(a_p\)。面积由投影像元面积除以像元中心处的椭球投影面积尺度近似得到，与现有 Workbench 面积方法一致。

对日期 \(i<j\)：

\[
\Delta h_{m,ij}(p)=h_{m,j}(p)-h_{m,i}(p),\qquad
V_{m,k,ij}=\sum_{p\in R_k\cap S}\Delta h_{m,ij}(p)a_p,
\]

\[
A_k=\sum_{p\in R_k\cap S}a_p,\qquad
\overline{\Delta h}_{m,k,ij}=V_{m,k,ij}/A_k.
\]

`positive_volume_m3` 对正高差积分，非负；`negative_volume_m3` 对负高差积分，非正；两者之和为 `net_volume_m3`。没有共同有效像元时三个值均留空，不能写成零。面积加权平均高差也留空。高差全为零且确实有有效像元时，体积才为零。

这些是表面高差的体积积分，未进行密度或质量换算，也没有自动归因为侵蚀、堆积或冰损失；雪、植被、建筑及地形平流等仍可能参与信号。没有根据阈值删去小高差，没有对缺测部分外推，也没有用像元数直接构造不考虑空间相关性的体积置信区间。

覆盖率 `common_fraction_within_aoi` 的分母是**目标位于已保存栅格分析区内的面积**，不是整个原始多边形面积。表格另列 `extends_outside_grid` 与 `cells_outside_aoi`，便于识别目标被裁掉的部分。正式比较应同时报告共同面积与覆盖率。相互重叠的目标分别统计，不自动相加；将重叠目标体积求和会重复计数。

本版会对所有日期组合导出统计，而不只对首末两期。目标最多 100 个，结果网格最多 1,200 万像元。批量较大时可取消；已写文件保留状态记录，不能把取消目录当作完整输出。

## 输出文件

所有新增文件位于新报告目录下的 `common_support/`：

| 文件 | 用途 |
|---|---|
| `analysis_domain_mask.tif` | 保存结果使用的分析区 |
| `common_valid_mask.tif` | 全方法全时相共同有效像元 |
| `common_validation_mask.tif` | 扣除所有拟合区后的共同验证像元 |
| `common_support.png` | 共同范围、验证区与目标边界概览 |
| `target_regions.geojson` | 参与这次统计的固定 ID 目标边界 |
| `regions.csv` | 目标覆盖、范围裁切信息和状态 |
| `region_pair_statistics.csv` | 每个目标、方法和两期组合的高差、面积、体积与描述性速率 |
| `common_validation_statistics.csv` | 共同验证像元上的最终栈诊断 |
| `summary.json` | 方法集合、排除记录、规则、输入文件哈希与完整统计 |
| `status.json` | 完成、失败或取消状态 |

掩膜编码为 1=入选、0=分析区内未入选、255=分析区外。概览图可能为显示而降采样，GeoTIFF 保留完整分辨率。原固定点 CSV 新增 `in_common_support`：点的数值仍保留，但明确指出该点是否位于全方法全时相共同范围内；共同范围不可用时这一项留空。

导出使用的是**已完成结果中保存的分析区和拟合/验证区**。在界面修改这些处理设置不会追溯改变旧结果；需要采用新设置时应另跑一个任务。目标区可以在导出时新指定，因此报告保留此次使用的目标几何与哈希。

## 如果要上传结果供下一步核对

软件开发可以先继续，不需要上传整套 DEM。若已经完成真实案例，建议先把新报告导出到当前 `work` 目录内，再运行本版 **RUN_04_COLLECT_RESULTS.bat**，上传生成的 `UPLOAD_TO_CHATGPT_ArcticDEM_时间戳.zip`。若工作区已经通过 GUI 切换到其他位置，请确认收集脚本使用的是那个目录；也可在 Anaconda Prompt 中用：

```bat
conda activate arcticdem_dod
python -m arcticdem_workbench bundle --workspace "D:\实际工作区\work"
```

该包收集 JSON、GeoJSON、CSV、日志、PNG、文本和 HTML（单文件小于 20 MiB），不包括 DEM 与 GeoTIFF 掩膜。它足以先核对流程、统计范围与报告；若需要独立复算某个异常位置，再补对应小区域栅格。尚未跑真实案例则无需为了上传而重复运行所有流程。
