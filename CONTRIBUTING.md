# Contributing

Describe the scientific or usability problem and provide a minimal reproducible example. Run the offline verifier before proposing changes. Preserve sampling/sign conventions, source quality screening before resampling, persistent object identifiers, missing values and explicit rejected-fit records.

Changes to registration methods require known-truth recovery and protected-change evidence. A low residual alone is insufficient. Do not modify the frozen joint-gradient engine in place: a scientific engine change requires a new identity, protocol and release version. Installation/documentation fixes should state whether numerical application modules changed.

Issues and pull requests should include the software version, Python/dependency versions and relevant logs. Do not upload credentials or entire private workspaces. Licensing follows LICENSE; third-party data and dependencies retain their own terms.
